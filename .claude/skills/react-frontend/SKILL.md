# cloud-storage frontend conventions

React 19, Vite, TypeScript, TanStack Router (file-based) and TanStack Query,
shadcn/ui on Tailwind v4, Biome, Playwright. Module root: `frontend/`.

**Package manager is `bun`.** The lockfile is `bun.lock`; there is no
`package-lock.json`. Never use `npm` commands here.

## Layout

```
frontend/src
├── client/           GENERATED from the backend OpenAPI schema — never hand-edit
├── components/
│   ├── ui/           shadcn/ui primitives — generated by the CLI, avoid editing
│   ├── Common/       shared app components (DataTable, Logo, NotFound, ...)
│   ├── Files/        per-feature components
│   └── Pending/      loading skeletons
├── features/         framework-free logic (hashing, categorisation, transfers)
├── hooks/            reusable React hooks (useAuth, useCustomToast, ...)
├── routes/           file-based routes; routeTree.gen.ts is GENERATED
└── lib/, utils.ts    helpers
```

## The generated client — the rule that matters most

`src/client/` is produced by `@hey-api/openapi-ts` from the backend's OpenAPI
schema, and `src/routeTree.gen.ts` by the TanStack Router plugin. **Both are
generated. Never hand-edit either.**

To change the API surface: change the backend, then from the repo root run

```
bash scripts/generate-client.sh
```

which regenerates the client and runs the linter over the result.

Hand-editing the client has already caused real drift in this repo — a schema file
silently lacked types that the backend had, because someone edited the SDK by hand
instead of regenerating. If the client looks wrong, regenerate; do not patch.

A backend change without a regenerated client is an incomplete change.

## Routing

- File-based via TanStack Router: a file under `src/routes/` becomes a route.
  `_layout.tsx` wraps authenticated pages; `_layout/` children inherit it.
- Validate search params with a zod schema in `validateSearch`, so URL state is
  typed and malformed URLs degrade predictably (see `_layout/files.tsx`, which
  falls back to `root`).
- Navigate with the typed `useNavigate()`/`Link`, never by mutating
  `window.location`.

## Data fetching

- TanStack Query for everything that touches the API. Never call `fetch` against
  the backend directly — go through the generated `client/` services, so auth and
  base URL handling stay in one place.
- Query keys are arrays that include every parameter the query depends on:
  `["files", path]`. A key missing a parameter serves stale data across
  navigations.
- After a mutation, invalidate the affected key rather than refetching manually.
- `useSuspenseQuery` with a `<Suspense>` boundary and a skeleton from
  `components/Pending/` is the established loading pattern.

## The one place raw fetch is correct

Presigned upload and download URLs point at object storage, not the API. Those
requests must **not** go through the generated client — see
`features/files/fileTransfer.ts`. The sequence is:

1. Ask the backend to presign.
2. `fetch` the returned URL directly with the returned method and headers.
3. Tell the backend the transfer completed.

Never route file bytes through the backend.

## Components and styling

- shadcn/ui primitives live in `components/ui/`, added via the shadcn CLI. Treat
  them as vendored: prefer composing around them over editing them.
- Tailwind v4 utility classes; merge conditional classes with `cn()` from
  `lib/utils`.
- Feature components live in `components/<Feature>/`; table column definitions go
  in that feature's `columns.tsx`.
- Framework-free logic belongs in `features/` so it can be reasoned about and
  tested without React.

## Formatting and lint

- Biome, configured in `biome.json`: double quotes, semicolons as needed, spaces.
- `bun run lint` runs `biome check --write` — it **modifies files**. After running
  it, check `git status`; a dirty tree means the lint step effectively failed for
  CI purposes.
- Biome also enforces import ordering and accessibility rules. A Biome version
  bump can newly flag previously clean files; that is a real failure to fix, not
  noise to suppress.

## Testing

- End-to-end only, with **Playwright**. There is no Vitest in this project.
- Specs live in `frontend/tests/`; helpers in `frontend/tests/utils/`.
- Tests need the whole stack running, and authenticate via `auth.setup.ts`.
- `@playwright/test` in `package.json` must match the image tag in
  `Dockerfile.playwright`. A mismatch produces "Executable doesn't exist" naming
  two versions — a configuration error, not a test failure.
- Run: `bunx playwright test`, or `docker compose run --rm playwright bunx
  playwright test` as CI does.

## Build / run

From `frontend/`: `bun run dev`, `bun run build` (`tsc` then `vite build` — type
errors surface only here), `bun run lint`, `bunx playwright test`.

`VITE_API_URL` selects the backend and is baked in at build time, so it differs
between the dev server, the compose frontend, and the Playwright container.
